# 1.4.0

Discord module: JDA-based bot API.

## Added

- `discord` module, wired into `settings.gradle.kts` and depending only on `commons` + `net.dv8tion:JDA:6.0.0-rc.5`. Primitives only — no bundled features:
  - `DiscordConfig` — bot token / command-registration guild, `@Config`-driven.
  - `DiscordCommand`/`DiscordCommandHandler` annotations, `DiscordCommandException`, `DiscordCommandProcessor` — slash command definition and dispatch for a single annotated instance.
  - `DiscordCommandManager` — implements `commons.command.CommandManager`; registers processors and pushes slash command definitions to Discord (guild-scoped or global).
  - `ComponentRegistry` — custom-id-keyed handler registry for buttons and modals.
  - `DiscordReadyEvent`/`DiscordEventBridge` — bridges JDA's ready event onto the commons `EventBus` as a `LuxEvent`, extensible to more JDA event types without exposing JDA types to consumer code.
  - `UtilRole`/`UtilUser` — role check/grant/revoke and Discord user lookup/DM helpers, no fixed schema or mapping.
  - `InteractionListener`, `DiscordBot` — JDA lifecycle wrapper; `start()` returns a `Result` instead of throwing into the host plugin's enable sequence.
- Design spec: `docs/superpowers/specs/2026-08-15-discord-module-design.md`. Implementation plan: `docs/superpowers/plans/2026-08-15-discord-module.md`.

## Notes

- Account linking, role-sync business rules, and per-game-event notification templates are explicitly out of scope — those require a consumer's own schema/business rules and are built on top of these primitives, not shipped by this module. `commons/discord/{DiscordWebHook,DiscordEmbed}`'s existing one-way notification API is unchanged.
- No privileged Gateway intents are required by anything in this module.
