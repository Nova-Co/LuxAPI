# LuxAPI Development Roadmap

## 🔴 CRITICAL — Fix Before Anything Else
*Found 2026-08-13 via deep code-level audit (content-level, not just structure) of `commons`/`core`/`fabric`/`neoforge`/`bukkit`. Verified by direct read, not just agent report — full call chains traced.*
- [x] ~~Permission enforcement is completely bypassed on Fabric and NeoForge for every annotation-driven command.~~ `commons/command/CommandProcessor.kt:48,56` correctly gates `@Command`/`@SubCommand` execution on `sender.hasPermission(permission)` — the check itself is real and correct. But `fabric/player/FabricLuxPlayer.kt:42-44` and `neoforge/player/NeoForgeLuxPlayer.kt:44-47` both hardcode `hasPermission(permission: String): Boolean { return true }` (NeoForge's has `// TODO: Map to NeoForge PermissionAPI later if needed`; Fabric's has no comment at all). `FabricCommandManager.kt:102-108` / `NeoForgeCommandManager.kt:102-108` both wrap the executing player as exactly this class before calling `processor.process()`. **Net effect: any player, with any or no permissions, can execute any permission-gated command registered through the Fabric/NeoForge command framework — on both of LuxAPI's two actual Cobblemon-supporting platforms.** Tests bake the bug in as expected behavior: `FabricLuxPlayerTest.kt:60` / `NeoForgeLuxPlayerTest.kt:55` both assert `hasPermission(...) == true` unconditionally — no test exists for the denied path because the implementation can't produce it. `bukkit/command/BukkitCommandSender.kt:46-48` does this correctly (delegates to native `sender.hasPermission(permission)`) — Bukkit is not affected. Fix: wire real permission checks (Fabric permissions API / NeoForge equivalent, or at minimum vanilla op-level as an interim floor) into both `hasPermission()` implementations, and add a test that exercises an actual denial. **Fixed 2026-08-13:** `FabricLuxPlayer` now delegates to `fabric-permissions-api:0.3.3` (LuxPerms-compatible); `NeoForgeLuxPlayer` uses the vanilla op-level 4 floor (NeoForge's own `PermissionAPI` requires static node pre-registration incompatible with this contract's arbitrary-string calls). See `docs/superpowers/plans/2026-08-13-permission-enforcement-fix.md`.
- [x] ~~Console/command-block execution is silently dead on Fabric and NeoForge.~~ Same two files, `FabricCommandManager.kt:101-109` / `NeoForgeCommandManager.kt:101-109`: `executeCommand()` sets `sender = null` when `!source.isPlayer`, then only calls `processor.process(...)` `if (sender != null)` — for console or command-block execution this is a complete silent no-op: no error message, no log, nothing happens. `CommandProcessor.buildArgumentsForMethod()` (commons) explicitly supports a plain `CommandSender` first parameter (not just `LuxPlayer`), meaning non-player execution was intended to work — the platform managers just never wire it in. `bukkit/command/BukkitCommandWrapper.kt:30-36` forwards any `CommandSender` (player or console) unconditionally — Bukkit is not affected. Fix: build a console-sender wrapper for both platforms (mirroring what `BukkitCommandSender` already does) instead of discarding non-player invocations. **Fixed 2026-08-13:** both platforms now route non-player senders through the existing `core.command.MinecraftCommandSender` instead of discarding them. See `docs/superpowers/plans/2026-08-13-permission-enforcement-fix.md`.
- [x] ~~`commons/event/EventBus.kt:11` — not thread-safe, inconsistent with the rest of the codebase's own pattern.~~ `listeners` is a plain `mutableMapOf`, while every other central registry in the same package uses `ConcurrentHashMap` (`ServiceManager.kt:12`, `MetadataContainer.kt:11`, `PlayerMetadataManager.kt:14`). `register()`/`unregister()`/`fire()` all mutate/iterate this map with zero synchronization. If any code fires or (un)registers events off the main thread (async DB callback, scheduler thread — both exist in this codebase), this is a real concurrent-modification risk, not hypothetical. Fix: switch to `ConcurrentHashMap` to match the established pattern. **Fixed 2026-08-13:** outer map switched to `ConcurrentHashMap`, inner per-event listener list switched to `CopyOnWriteArrayList` (the map alone wasn't enough — the inner list each event class maps to was also a plain `mutableListOf`, mutated/iterated without synchronization). Verified with a 200-thread concurrent-registration test that reliably reproduced lost listeners before the fix and passes reliably after.
- [x] ~~Permission system is inconsistently implemented across every path that isn't Bukkit.~~ Beyond the Fabric/NeoForge stub above: `core/command/MinecraftCommandSender.kt:44-46` (the separate Brigadier-native path used by `core/command/BrigadierCommandAdapter.kt`) ignores the `permission` string argument entirely and always checks vanilla op-level 2 (`source.hasPermission(2)`) — not broken the same way, but the API shape promises per-node granularity it doesn't deliver. Only Bukkit's implementation actually does what the `CommandSender.hasPermission(String)` contract promises. Worth resolving as one pass alongside the critical fix above, not two separate efforts. **Fixed 2026-08-13:** documented as a deliberate floor (not a gap) directly on `MinecraftCommandSender.hasPermission()` and on the `CommandSender` interface's fail-closed contract. See `docs/superpowers/plans/2026-08-13-permission-enforcement-fix.md`.

*Minor, non-urgent findings from the same audit, folded into Phase 13 below rather than listed here: `core/loot/LootManager.kt:24-27` silently no-ops on an unregistered `lootId` (no log); `commons/config/LuxConfig.kt:40-52`'s `reload()` would clobber any future non-persisted field on a `LuxConfig` subclass (currently inert, no such field exists yet, but a latent footgun).*

## 🟢 Phase 1: Multi-loader Architecture & Core Infrastructure (Completed)
*The baseline foundation that allows LuxAPI to run seamlessly on both Fabric and NeoForge.*
- [x] **Platform-Agnostic Bridge:** Unified `commons` and `core` modules mapping directly to `fabric` and `neoforge` implementations.
- [x] **Command Engine API:** Advanced Brigadier wrapper (`CommandEngine`, `InjectorRegistry`, `TabRegistry`) for creating complex server commands effortlessly.
- [x] **Universal Scheduler:** Cross-platform tick-based task scheduling (`LuxScheduler`, `TaskData`).
- [x] **Interactive GUI Builder:** Fluent API for chest GUIs and paginated menus (`GuiBuilder`, `PaginatedGuiBuilder`, `LuxMenu`).
- [x] **Player Abstraction:** `LuxPlayer` and `PlayerManager` for cross-platform player handling.

## 🟢 Phase 2: Data, Utility & External Hooks (Completed)

- [x] **Persistent Attributes:** `AttributeManager` and `MetadataContainer` for safely attaching custom data to players and entities.
- [x] **Discord Integration:** Out-of-the-box `DiscordWebHook` and `DiscordEmbed` builders for seamless server-to-Discord logging and events.

- [x] **Math & Cooldowns:** Built-in `CooldownManager`, `TimeGateManager`, `Cuboid` region math, and `RandomWeightedSet` tools.

Note: no separate `playAnimation(String, ...)`/`playSound(...)` wrappers were added — `NPCEntity` already exposes both as public members (`PosableEntity.playAnimation`, vanilla `Entity.playSound`) with identical signatures, so a same-signature extension would be dead, compiler-shadowed code; call those directly on the entity instead. ## 🟢 Phase 5: Battle Scripting & Interceptor API (Completed, rescoped to Cobblemon's real API)
- [x] **CustomBattleBuilder:** `LuxBattleBuilder` (`battle/BattleBuilder.kt`) + `BattleExtensions.kt` — wild/player/NPC forced battles, double-battle toggle. Implemented.
- [x] **BattleRuleManager:** `BattleRuleManager` — species bans, level caps, and a custom-rule escape hatch, enforced by cancelling Cobblemon's `BattleStartedEvent.Pre` before the battle launches. **Scope correction vs. original wording:** item restrictions and weather constraints are dropped entirely — verified against Cobblemon `1.7.3` source that no hook exists for either (its own `BattleFormat.ruleSet` only accepts a fixed set of Showdown clause strings; Cobblemon's own maintainer comment calls the closest thing, `adjustLevel`, a "stop gap... before a more general system is implemented"). `BattleStartedEvent.Pre` is the only real cancellable pre-battle hook, so species/level are the only enforceable constraints today. Implemented.
- [x] **Battle Event Interceptors:** `BattleInterceptor` — `onHealthThreshold(battle, target, threshold, action)` for cutscene-style triggers and `stopBattle(battle)` (wraps `PokemonBattle.stop()`, the correct general-purpose method — distinct from `BattleManager.executeCrashSafeTurn`'s lower-level `closeBattle()`, which is crash-recovery-only and skips normal teardown). **Implementation note:** Cobblemon has no HP-changed event for in-battle Pokémon (confirmed via source grep — zero results), so thresholds are evaluated via 1-second `LuxScheduler` polling per active battle, not event subscription; poll tasks are cleaned up on `BATTLE_VICTORY` via `npc/battle/BattleEventListener.kt`. **Known gap:** cleanup only hooks `BATTLE_VICTORY` — a battle ended by fleeing or by `stopBattle()` itself leaks its poll task until server restart; flagged during design, not fixed in this pass. Implemented.

## 🟢 Phase 6: Safe Storage & Party Transactions (Completed)
- [x] **PokemonTransactionAPI:** `PCStorageManager.depositToPC()`/`withdrawFromPC()` (+ `LuxPlayer.depositPokemonToPC()`/`withdrawPokemonFromPC()` extensions) — mirrors Cobblemon's own `MovePartyPokemonToPCHandler`/`MovePCPokemonToPartyHandler` packet-handler logic exactly (`store.remove()` then `otherStore[position] = pokemon`, fully packet-synced via Cobblemon's own `PokemonStore` overrides), including the `preventCompletePartyDeposit` server-config guard. **Deliberate deviation from upstream:** if an explicit destination slot is given and already occupied, this fails loud (`false`) instead of silently redirecting to the first available slot the way Cobblemon's in-game PC screen does — a raw dev-facing API silently placing a Pokémon somewhere other than the coordinates the caller specified is a footgun. Implemented.
- [x] **Anti-Duplication Guards (PC-side):** `PCStorageManager.move()` now delegates to `PCStore.swap()` instead of raw box mutation, closing the client-desync dupe-risk found this session. Note: a separate, more serious duplication/data-loss gap exists in the *GTS* system — see Phase 8.
- [x] **Property Manipulation Wrapper:** `PokemonPropertyManager` (+ `Pokemon.setNature()`/`setHeldItem()` extensions) — safe, sync-aware IV (0-31), EV (0-252/510 total), nature, and held-item mutation. IV/EV delegate to Cobblemon's own `Pokemon.setIV()`/`setEV()` members (not the raw `ivs[stat]=`/`evs[stat]=` operators — those skip the max-HP recalculation Cobblemon's own methods do when the HP stat itself changes, a correctness bug caught during implementation), nature/held-item delegate to the `Pokemon.nature` setter and `Pokemon.swapHeldItem()`; Cobblemon itself handles client sync and persistence-dirty marking regardless of which store the Pokémon currently lives in. **Note:** no `Pokemon.setIV()`/`setEV()` extension wrappers were added — `Pokemon` already exposes public members with the identical signature, so a same-signature extension would be dead, compiler-shadowed code (same pattern as the `NPCFxExtensions` case in Phase 4); call `PokemonPropertyManager.setIV()`/`setEV()` directly for the validated Boolean-return version, or `pokemon.setIV()`/`setEV()` directly for raw Cobblemon behavior. **Deliberate deviation from upstream:** `setHeldItem()` defaults `decrement = false`, opposite of `swapHeldItem()`'s own default of `true` — that default exists for consuming an item out of a player's hand mid-interaction, which doesn't apply to a dev constructing an `ItemStack` value to assign as a property. Implemented.

## 🟢 Phase 7: Dynamic Spawning & Area Controllers (Completed)
- [x] **AreaSpawnManager:** `AreaSpawnManager` (`spawning/AreaSpawnManager.kt`) — register/unregister region-scoped `SpawnArea`s (dimension + `Cuboid` region + spawn-weight multiplier + banned species), enforced via a single stateless `LuxAreaSpawningInfluence` wired into Cobblemon's real `PlayerSpawnerFactory.influenceBuilders`. **Scope note:** uses LuxAPI's own axis-aligned `Cuboid` for regions rather than Cobblemon's native spherical `SpatialSpawningZoneInfluence` — that system is tied to ephemeral per-tick zone-generation internals with no stable global attachment point, whereas `PlayerSpawnerFactory` is a genuinely public, one-time registration point and lets the API reuse a type devs already know from Phase 2. The influence live-queries the registry on every spawn check (never a snapshot), so area changes apply immediately even to players who already have a spawner. Implemented.
- [x] **DynamicEncounterAPI:** `SwarmManager`/`SwarmEvent` — timed swarm/outbreak events with species, level range, radius, and active-entity cap, driven by a self-cancelling scheduled task. Implemented.
- [x] **Spawn Event Interception:** `SpawnInterceptor.onPokemonSpawn()` — wraps Cobblemon's own `CobblemonEvents.POKEMON_ENTITY_SPAWN` (fired for every natural spawn attempt, before the entity enters the world) in a plain listener callback carrying entity/world/position/species and a `cancel()`, so devs don't need to touch Cobblemon's `Observable`/`Cancelable` plumbing directly. `PokemonSpawner.kt`'s direct-spawn helpers are unchanged — this is a separate, complementary hook into *natural* spawns, not a replacement for manual spawning. Implemented.

## 🟢 Phase 8: Economy & Trade Hooks (Completed)
- [x] **TradeInterceptorAPI:** `TradeInterceptor` (`trade/TradeInterceptor.kt`) — `onTradeAttempt()`/`onTradeCompleted()` wrap Cobblemon's real `CobblemonEvents.TRADE_EVENT_PRE`/`TRADE_EVENT_POST`, fired by its native player-to-player `TradeManager`. Same cancelable-listener pattern as Phase 7's `SpawnInterceptor`. Implemented.
- [x] **GTS/Economy Helpers (appraisal):** `PokemonPriceCalculator` + `LuxPokemonEconomy`'s pluggable `PokemonAppraiser` chain for dynamic valuation. Implemented (carried over from the prior pass).
- [x] **GTS Listing/Purchase — dupe/data-loss bug fixed:** `GlobalTradeManager.listPokemon()` now really serializes the Pokémon via the existing `PokemonSerializer` and removes it from the seller's party (respecting the `preventCompletePartyDeposit` guard, same rule as Phase 6's PC deposit). `purchaseListing()` deserializes the *real* listed Pokémon and verifies the buyer has party/PC space *before* any funds move — a buyer is never charged for a trade that can't complete — then grants the actual Pokémon (not a blank placeholder). **Added beyond the original TODO wording:** `cancelListing()`, so a listed Pokémon isn't permanently stuck unless it sells — the listing is only removed once the Pokémon has actually been handed back to the seller. Implemented.
- [x] **Trade Tax Injection:** `TradeTaxManager` (`economy/TradeTaxManager.kt`) — pluggable `TradeTaxCalculator` chain, same fold-over-registered-rules shape as `LuxPokemonEconomy`'s appraisers, applied to the seller's payout at GTS purchase time. Result is clamped to `[0, price]` (deliberate deviation from the unclamped appraiser chain — this number directly moves real funds, so a misconfigured rule can't invert or drain a payout). No calculators registered → 0% tax, fully backward compatible. **Scope note:** tax only applies to GTS purchases — vanilla Cobblemon player-to-player trades carry no currency, so there's no attachment point there without inventing a currency side-channel nothing else in the codebase has. Implemented.

## 🟢 Phase 9: Cinematic & MoLang FX Wrapper (Completed)
- [x] **MoLangCinematicAPI:** `MoLangCinematicAPI` (`fx/MoLangCinematicAPI.kt`) — generic wrapper around Cobblemon's real `ActionEffectTimeline`/`ActionEffectContext`/MoLang engine (the same system driving move animations in battle), usable against arbitrary entities outside of battle. `playTimeline(id, level, users, targets, queries)` runs a datapack-registered `action_effects` timeline (via `ActionEffects.actionEffects`); `playTimeline(timeline, ...)` runs a hand-built/parsed one; `parseTimeline(json)` builds an ad-hoc `ActionEffectTimeline` from a JSON string using Cobblemon's own `ActionEffects.gson` (same keyframe schema: `animation`, `molang`, `sequence`, `parallel`, `entity_particles`, `entity_sound`, `move_to_target`, etc.) without needing a real datapack file; `resolve()` evaluates a one-off MoLang expression string server-side; `runClientMoLang()` sends raw MoLang strings straight to an entity's client-side posable runtime (pure-string packet, touches no MoLang types at all). Internally builds the `MoLangRuntime`/`UsersProvider`/`TargetsProvider` scaffolding that Cobblemon's own battle code (`MoveInstruction`) builds inline — LuxAPI is the first place this exists as a reusable, non-battle-scoped entry point. **Classpath fix (was flagged in Phase 13):** added `compileOnly("com.bedrockk:molang:1.1.20")` to `cobblemon/build.gradle.kts` — since Cobblemon's `mod` artifact is intentionally `isTransitive = false`, `ActionEffectTimeline`/`MoLangRuntime` directly reference `com.bedrockk.molang.*` in their public signatures, which otherwise triggers a "may be forbidden soon" compiler warning (same one seen in Phase 4). `compileOnly` silences it cleanly with zero runtime effect (the real classes are supplied by Cobblemon's own jar at runtime) — verified via a full `./gradlew build`, zero bedrockk warnings emitted. Implemented.
- [x] **Pre-built Animation Triggers:** `BossFxWrapper.GenericAnimation` + `playAnimation()`/`playCry()`/`playEntityEvent()`. Implemented.
- [x] **Particle & Sound Utilities:** `playSnowstormEffect()`, `playMoveParticle()`, `playSound()`, `spawnParticles()` — comprehensive wrapper around Cobblemon's Snowstorm packets and vanilla particles/sounds. Implemented.
